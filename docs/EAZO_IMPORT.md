# Eazo 导入与后续开发说明

本项目由 `molan-os-main.zip` 导入，保留原有 React/Vite + Hono 架构、技能包和业务流程，没有替换为新模板。按创作者明确要求，从历史快照恢复「墨的引力 / The Unwritten」界面，并在其确认后精修响应式与操作细节：侧栏导航、文学标题、19 页纸雕、出版物式书封与物理动效均保留。后续的 Molan Editions 与写作列表版不再加载；书稿、模型配置和服务端业务不回滚。下文保留各轮变更与验证记录。

## 启动与检查

- Node.js：22.19.0 或更新版本。
- 安装依赖：`npm ci`。
- Eazo 预览：`npm start`（等同 `npm run dev:eazo`）。
- 类型检查：`npm run typecheck`。
- 前端生产构建：`npm run build`。
- 原项目完整回归：`npm run test:audit`。
- 导入兼容回归：服务启动后运行 `npm run test:import`；需先安装 Playwright Chromium。该测试会创建并在结束时清理专用测试书稿，不会清空书库。

`scripts/eazo-dev.mjs` 读取服务端 `.env`，将 Vite 提供在公开端口 3000，Hono 保持在回环地址的 8787 端口。前端通过同源 `/api` 代理访问后端，保留原有可信来源检查。`PORT`、`MOLAN_API_PORT` 可覆盖端口；`EAZO_PREVIEW_URL` 用于精确配置预览来源。不要把 API Key 或数据库连接字符串添加到客户端环境变量。

## 核心业务约束

1. 数据库是权威来源；默认 SQLite 文件位于 `data/changjuan.sqlite`，`data/books/` 是书稿的 Markdown 镜像。
2. 保存使用版本比较，避免旧页面静默覆盖新稿；修改编辑逻辑时需保留冲突处理和候选稿机制。
3. 正式定稿、记忆提案和批准是不同操作；正文变化不应直接绕过批准覆盖故事知识。
4. 批量任务由后端 worker 推进，不依赖页面持续打开。
5. `local-draft` 是内置结构化中文草稿，不是真实远程大模型；远程模型未配置时不会悄悄改用它。
6. pi-agent 集成用于模型代调，不代表已经实现自主工具编排。

## 小说搜索、蒸馏与私人参考库（2026-10-11，当前增量）

### 使用流程与边界

- 新入口 `/references`，主导航「参考库」；技能页与书稿上下文面板也可进入。沿用已确认的「墨的引力」视觉，新增 `atelier-references.css`，不替换书库或三栏写作区。
- 搜索作品 → 读取目录 → 选章下载；也可导入 / 粘贴 TXT、Markdown，支持 UTF-8 / GB18030。先确认有权使用内容，导入不会创建书稿或调用模型。可下载自己库内的原文 TXT。
- 蒸馏使用创作者已确认的 **Qwen3.8 Flash**，独立于原有写作场景的模型设置。这里的“蒸馏”是结构化提炼方法，不是训练或更新模型权重。
- 选取章节与开局 / 结构 / 节奏 / 文风，分块生成待审方法卡。每张卡含机制、迁移方式、使用边界，以及经过服务端逐字核验的来源摘句、章节、字符范围和内容 hash；证据不匹配、输出截断、长段抄写或结构错误会拒收当前分块。
- 审阅通过并明确同意提供给当前工作区后，才可绑定书稿；撤回审阅立即取消全部绑定。每本书最多 24 张绑定卡，Agent 按场景最多取 6 张、5,500 字，不截断单卡。
- Agent 只得到方法及来源信息，不得到原文章节或证据摘句；外部资料不是指令、本书事实、设定或正式记忆，`memory_extract` 不取参考卡。不改变原有 CAS 保存、定稿、记忆提案与批准边界。删除书稿只删绑定，不删资料所有者的私人原文。

### 认证、来源与费用

- 参考资料 API 统一使用 `@eazo/sdk@0.22.13` 的 `requireAuth`，浏览器通过集中 API 层携带 SDK session 与语言；owner 和 `viewer_user_id` 只取服务端验证的身份。浏览器不能指定模型、凭据、provider URL 或其它用户身份。
- 原文、方法卡、任务、下载和导出均按 Eazo 用户查询，跨用户与不存在返回相同的 404。退出 / 切换账户清理私人界面、导入草稿和同意状态，并丢弃上一个账户迟到的响应。
- **旧书稿业务仍是单实例共享工作区，不是全站多用户隔离。** 只有参考库数据新增用户隔离；绑定方法卡时已明确提示将其提供给共享写作工作区。发布为多人服务前仍须单独处理旧书稿身份、访问隔离及生产存储。
- 上传的 Windows EXE 仅静态分析，未执行；重建的是网页搜索、选章与下载功能，不在网页或服务端执行该二进制，也不开放任意服务器目录。
- 兼容附件中识别的 shukuge.com 书源。目前读取公开 HTTP 页面；HTTPS 证书问题未通过关闭 TLS 校验绕过。固定域名 / 路径、解析公开 IP 并锁定连接地址，限制重定向、响应大小和目录范围，不接受任意 URL；不绕登录、付费、反爬或受限章节。第三方 HTTP 内容不保证完整或可信，来源不可用时可导入有权使用的文本。
- 单来源最多 200 万字 / 2,000 个文本章节，单次下载最多 200 章；每次蒸馏 100–48,000 字、8,000 字一块、最多 6 次模型请求。每用户最多 100 个来源；滚动 24 小时最多 20 个任务，全局最多 60 个；每用户最多 1 个活动任务，全局最多 2 个。下载和蒸馏都计入处理次数。
- 后台任务先持久化，再推进真实分块 / 下载进度；取消保留已完成内容，不承诺退还已消耗额度。服务重启将未完任务标记为中断，不自动重放收费请求。删除来源清理正文、卡和绑定，同时保留防刷限额所需的最小任务用量元数据，不允许靠删除来源重置日限额；当前没有定时 TTL 清理承诺。
- 模型配置与凭据均留在服务端。Vite 为 SDK 提供最小公开 `process` / `process.env` 兼容对象，只含环境模式与公开 App ID，修复开发环境正常、生产构建 SDK 却读不到 App ID 的问题；不把完整环境、私有地址或模型 key 注入前端。
